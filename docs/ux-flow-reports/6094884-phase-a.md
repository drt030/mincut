## Flow A1 — Default radial overview legibility

### Step 1 — Navigate `/graph`, screenshot the default viewport

- screenshot: `.tmp/phase-a-tour/a1-step1-default-clean.png`
- observed: Default ReactFlow viewport opens at scale(1) translate(0,0). The 63-node radial layout extends from roughly (-908,-914) to (1083,683) in unscaled coordinates, far larger than the 896×588 canvas viewport. As a result, the **default viewport shows almost no nodes** — only the central handful are even on-screen. The header (能力图谱探索器) is present; the page H1 has been deleted as planned. The right-hand detail panel (~30-35% of width) still shows the OLD design's full body: focal product card, Risk/Maturity/Cost stat tiles, "Top blockers" pill banner, Maturity badge, Maturity-over-time, Metrics. The legacy detail panel is expected per Phase-A scope (B4 will rewire to 64px rail).
- DOM diff vs the OLD design: ZERO mode tabs, ZERO KPI counter row above the canvas, ZERO advanced-filter dropdowns, ZERO color-mode selector, ZERO "图谱浏览器" H1. The deletion landed.
- score: clarity 2 / responsiveness 4 / fit-for-purpose 2
- notes: The "Top blockers" yellow card persists in the **right panel** (not as a top-of-canvas banner as the ADR's "transitional exception" describes). Whether that's a regression or a deliberate relocation depends on interpretation — flagging for Phase B/C review. **The default zoom failing to show the radial pattern is the biggest A1 issue**: a new user opening `/graph` would see an almost-empty white canvas and 8 fragments of dots at the lower-left, with no obvious affordance to fit-view. Auto-fitView on mount is a strong recommendation.

### Step 2 — Inspect canvas DOM at default zoom (after manual fitView)

- screenshot: `.tmp/phase-a-tour/a1-step1-after-fitview.png` and `.tmp/phase-a-tour/a2-band1-zoom0_33.png`
- observed: After clicking the built-in fitView button, viewport drops to zoom 0.326234 (band 1). DOM shows 63 `.react-flow__node` elements, each with one `<circle r="5">` per spec. Distinct fill colors: 13 saturated hues + neutral grey (rgb(145,145,154) for the React Flow attribution badge, hsl(0,0%,60%) for 17 nodes = focal product + materials + shared-multi-parent modules). Edge layer (`.react-flow__edges` div) is **EMPTY** — 0 paths rendered.
- score: clarity 3 / responsiveness 5 / fit-for-purpose 3
- notes: **Console emits 4620 `[React Flow]: Couldn't create edge for source handle id: "null"` warnings** (one per edge × repeats over re-renders). Radial nodes don't declare handles; ReactFlow refuses to draw edges. The ADR explicitly says "thin grey edges" should render in Phase A. **This is a real Phase-A gap, not a Phase-B deferral.** Either A3/A4 needs handles on the radialDot node OR an SVG-overlay edge layer that bypasses ReactFlow's handle requirement. Without edges, the DAG topology — the entire point of the redesign — is **invisible** even at the correct zoom band. The neat radial-arc pattern is partly readable from node positions alone, but no parent-child structure is conveyed.

## Flow A2 — LOD band transitions

### Step 1 — Establish zoom-level controls

- observed: Clicking the built-in ReactFlow `+`/`-` buttons via `.click()` did NOT change zoom (synthetic clicks on the controls don't trigger ReactFlow's internal zoom handler). Wheel events with `ctrlKey: true` (pinch-zoom signal) work and were used to step through bands. ReactFlow's max zoom is ~2.5; below ~0.32 the layout doesn't shrink further (matches `minZoom` default 0.5 scaled by fitview overshoot).
- responsiveness: smooth, no visible jank.

### Step 2 — Band 1 at zoom 0.33: pure 5px dots, no text

- screenshot: `.tmp/phase-a-tour/a2-band1-zoom0_33.png`
- observed: 63 nodes, all `<circle r="5">`. Each node wrapper is 18×18 px (10px circle + padding). NO `<text>` element rendered, NO `<foreignObject>`, NO outline (per band-1 spec: "fill = pure family hue, no lightness variation"). Labels invisible, hue legible.
- score: clarity 4 / responsiveness 5 / fit-for-purpose 4
- notes: This is the cleanest band. Matches A4 spec exactly. Only issue carrying over from Flow A1 is missing edges.

### Step 3 — Band 2 at zoom 0.97: 12px markers + truncated names + outline

- screenshot: `.tmp/phase-a-tour/a2-band2-zoom0_97.png`
- observed: 63 nodes, each `<circle r="12">` with `stroke="#888"` outline width 1.5px, plus inline `<text>` showing truncated names. aria-labels populated (e.g., `30 万 RMB 包裹分拣机器人 · 产品`). aria-pressed reflects selection. The dot wrapper is 72×42 px (per zoom 1 node sizing).
- score: clarity 4 / responsiveness 5 / fit-for-purpose 4
- notes: Names truncate appropriately. Outline = neutral `#888` not a mode-band color (B1 will introduce mode-band outlines). No collisions visible at this zoom in the focal-subtree dense quadrant.

### Step 4 — Band 3 at zoom 2.5: 80×40 HTML cards with full name + maturity badge

- screenshot: `.tmp/phase-a-tour/a2-band3-zoom2_5.png`
- observed: `<foreignObject>` with inline HTML divs renders for all 63 nodes; each card is 80×40, background = subsystem hue mapped to RGB (e.g., rgb(215,66,92) for red-pink), 1px slate border, padding 2/4px, font-size 9px. Card text = full node name + maturity level on a second line ("prototype" / "commercially_available" / etc.).
- score: clarity 3 / responsiveness 5 / fit-for-purpose 3
- notes: **Layout extent grows quadratically; at zoom 2.5 the cards spread off-viewport.** My band-3 screenshot shows an empty grid because the layout had already panned the visible region to a sparsely-populated quadrant. Once you manually pan to a dense area the cards render correctly — but **cards-on-grid + no recenter on zoom-in = user gets lost**. Recommend an auto-fit/recenter on band-crossing transitions in Phase B polish. Also: maturity "badge" is rendered as inline lowercase text not a styled badge — minor styling deficit vs ADR's "1 mode-relevant badge".

### Step 5 — Smoothness of band transitions

- observed: no DOM thrash visible during wheel-zoom; node count stays constant at 63; node DOM is replaced on band boundary (circle-only → circle+text → foreignObject) but the replacement is single-render and CSS-driven, no flicker. Quantization at `Math.floor(z*2)/2` works — small zoom changes within a band do not re-render the node component. Confirmed via the agent-memory note about ZoomContext bridge.
- score: clarity 4 / responsiveness 5 / fit-for-purpose 4
- notes: One subtle issue — the band-1 → band-2 transition crosses zoom 0.5; on the way from 0.33 to 1.0 the band-2 names appear suddenly without scaling animation. Acceptable for v1.

The 64px rail / 400px expanded contract from B4 has not landed.
